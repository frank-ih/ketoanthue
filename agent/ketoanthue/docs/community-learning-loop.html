SUB-WORKFLOW — ADDITION TO LEARNING PLAN

Community-Driven Learning Loop

Social Scout Agent harvests real accounting questions from communities → Accounting Agent attempts to solve → knowledge gaps trigger deep research → confirmed answers auto-adopted into the knowledge base. The agent gets smarter every day from real-world problems it couldn't previously solve.

💡
Why This Sub-Workflow Exists

The static ingestion pipeline (crawling laws and publications) gives the agent its foundation. But real-world accounting is messy — practitioners face edge cases, ambiguous situations, and novel transaction types that no textbook covers. Community questions are the richest signal for what the agent doesn't yet know.

🎯 Gap Discovery

Community questions reveal precisely where the agent's knowledge has holes. A question the agent can't answer at >95% confidence = a gap to fill. This is far more targeted than blanket crawling.

🔄 Self-Healing Knowledge

The agent doesn't just flag gaps — it actively researches, validates, and patches them. Each resolved question becomes a new knowledge unit that prevents future gaps on the same topic.

📈 Demand-Driven Priority

Questions that appear frequently across communities get higher research priority. The agent learns what practitioners actually struggle with, not what we assume they need.

🤖 Two Agents Working Together via A2A (NATS)

Social Scout Agent

Variant of the SocialAdvocate template. Monitors Facebook groups (Kế toán tổng hợp, Hỏi đáp kế toán thuế, etc.), Zalo groups, accounting forums. Identifies accounting-related questions, deduplicates, extracts structured question + context, and forwards to the Accounting Agent via A2A.

NATS subject: agent.accounting.community_question

Accounting Agent

Receives the question. Runs the full consultation pipeline: context assessment → clarification/scenario generation → solution attempt → confidence scoring → deep research loop (if needed) → knowledge adoption. The Accounting Agent is both the answerer and the learner.

NATS subject: agent.accounting.knowledge_adoption

6
Human Expert Escalation Human Review Queue
If 5 research cycles can't push confidence to ≥ 95%, the question is genuinely hard or novel. The agent:

1. Packages its best-effort answer + all research findings + confidence breakdown into a review ticket.
2. Routes to a human accounting expert (via dashboard notification or email).
3. The human reviews, corrects if needed, and approves the final answer.
4. The human-approved answer enters Stage 7 as a gold-standard knowledge unit (highest trust within adopted knowledge).

The agent NEVER publishes an answer to the community below 95% confidence. Silence is better than a wrong accounting answer.

Community Response (Optional) Social Scout Agent
The verified answer is sent back to the Social Scout Agent, which drafts a helpful, professional reply to the original community post. The reply includes:

1. The answer with journal entry details
2. Supporting regulation citations (e.g., "Theo Thông tư 133/2016, Điều 86…")
3. Explicit assumptions if scenario was auto-generated

This step is optional and configurable — it can be disabled if the tenant only wants passive learning, not community engagement.
🛡️
Safety Rails & Anti-Patterns

This loop is powerful but dangerous if unchecked. These are the hard rules that prevent bad knowledge from contaminating the base.

🚫 Never Auto-Adopt Below 95%

No knowledge unit with confidence below 95% enters the knowledge base without human review. The 95% threshold is not configurable by tenants — it's a platform invariant for accounting agents. Financial accuracy is non-negotiable.

🚫 No Circular Reasoning

The agent cannot use its own previous community answers as Tier 1 evidence for new answers. Adopted knowledge units are tagged COMMUNITY_DERIVED and can only supplement — never override — Tier 1-2 sources.

🚫 No Stale Adoption

Knowledge units inherit the effective date range of their supporting regulations. When a regulation is superseded (e.g., TT200 → TT99), all KUs that cite it are automatically flagged for re-validation or deprecation.

⚠️ Contradiction Detection

Before adoption, every new KU is checked against existing knowledge for contradictions. If a new KU says "Dr 642" but existing KU says "Dr 641" for the same scenario → both are quarantined and flagged for human review.

⚠️ Rate Limiting

Max 50 knowledge units adopted per day without human review. Spike detection: if adoption rate suddenly jumps (e.g., new regulation causes flood of questions), the system switches to batch review mode requiring human approval.

⚠️ Scenario Variant Awareness

The agent must never adopt a single-scenario answer as universal truth. If a question could have different correct answers under different assumptions (TT99 vs TT133, SME vs enterprise), all variants must be captured in the knowledge unit.

🔄 Meta-Agent Integration

The meta-agent observes this sub-workflow via OTel traces and optimizes over time:

  • First-attempt success rate trending up? → The knowledge base is getting healthier. The agent is learning.
  • Same question type repeatedly failing? → Systematic knowledge gap. Trigger a bulk ingestion of the relevant regulation area.
  • Research cycles consistently maxing out (5/5)? → The Tier 1 sources may have coverage gaps. Escalate to platform team to add new sources.
  • Human expert corrections reveal patterns? → Use corrections as DPO training signals to improve the agent's reasoning quality.
  • Community engagement on responses (likes/thanks)? → Positive signal → boost confidence of corresponding knowledge units.

💡 The Flywheel Effect

More community questions → more knowledge gaps discovered → more research → more knowledge units adopted → higher first-attempt success rate → better community responses → more trust → more questions → the loop accelerates. After 6 months, the agent should answer >85% of community questions at ≥95% confidence on first attempt — meaning it has deeply learned the practical edge cases that no textbook covers.
